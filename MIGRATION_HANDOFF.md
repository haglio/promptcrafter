# PromptCrafter: React/Electron → PyQt6 Migration Handoff

## What this is

PromptCrafter is a config-driven prompt crafting UI currently built with React 19 / TypeScript / Electron. It needs to be switched to PyQt6, using `shared_ui` (at `../../../shared_ui/`) for shared design tokens (colors, fonts, spacing).

A previous attempt deleted the React source and test suite, wrote a PyQt6 app from scratch with shallow replacement tests, and had to be fully reverted because the app was broken and the tests didn't catch it. **Do not repeat that approach.**

## Current state

- **Main branch is the original React/Electron app**, fully working, all tests green
- 8 Python tests pass: 7 launcher contract tests + 1 vulture dead-code test
- The JS test suite (Vitest) is at `src/test/` — these are the specification:
  - `prompt.test.ts` (462 lines, 60+ tests) — prompt generation for all 13 control kinds, weights, supplements, substitutions, plurality, revealed-bys
  - `state.test.ts` (78 lines) — toggle state management, initial state creation
  - `app.test.tsx` (740 lines) — full UI integration tests covering all user interactions
  - `csv-to-schema.test.ts` (138 lines) — CSV schema converter tests
  - `fixtures/testSchema.ts` (450 lines) — canonical test schema used by all tests

## How to do this with TDD

The test suite IS the app specification. The migration must be test-driven:

1. **Port one test at a time from the Vitest suite to pytest.** Write the Python test, confirm it fails (red), then write the minimum production code to make it pass (green), then refactor.

2. **Start with the business logic tests** (`prompt.test.ts`, `state.test.ts`) — these are pure functions with no UI dependency. Port the types, state, and runtime modules driven by these tests.

3. **Then port the UI tests** (`app.test.tsx`) — these test user interactions (clicking radio buttons, toggling checkboxes, checking prompt text updates). The PyQt6 widgets must pass the same behavioral assertions.

4. **Keep the original source intact as reference** until the Python equivalent passes the same tests. Don't delete `src/` until the Python test suite covers what the JS test suite covers.

5. **The launcher contract tests** (`test_launcher_contract.py`) are Electron-specific and will need to be replaced with PyQt6 equivalents when the shortcut/launcher changes.

## shared_ui library

Located at `C:/path/to/suite-root/projects/shared_ui/`. Provides:
- `colors.py` — 32 QColor constants (BG_PRIMARY, TEXT_PRIMARY, BLUE, TOGGLE_ON, etc.)
- `fonts.py` — `make_font()` factory, FONT_UI="Segoe UI", sizes (HEADING=14, BODY=11, SMALL=9, TINY=8)
- `spacing.py` — MARGIN_STANDARD=8, GAP_SMALL=4, GAP_MEDIUM=8

Currently integrated via CSS custom properties (`src/tokens.css` generated by `shared_ui/generate_web_tokens.py`). The PyQt6 version should use the Python tokens directly.

## Taskbar shortcut

The app launches from a Windows Taskbar icon via `scripts/Update-PromptCrafterShortcut.ps1`. When the migration is done, update that script to point at `pythonw.exe -m promptcrafter` instead of Electron. The AppUserModelId is `Alex.PromptCrafter`.

## What NOT to do

- Do not delete the React source or test suite before the Python equivalents are green
- Do not write "replacement" tests that test different things than the originals
- Do not batch-write multiple tests before production code
- Do not rebuild the entire UI on every interaction (the previous attempt did this and it caused window barrages — Qt widgets should update in place)
